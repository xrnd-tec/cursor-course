# 16. ブラウザと Design Mode

Agents Window（[12-agents-window.md](12-agents-window.md)）にはブラウザが載っています。**動いているアプリを Agent に見せながら直させる**ための場所です。

コードだけを渡すのと違い、「実際にこう表示されている」という結果を根拠にできます。

## ブラウザでできること

- ローカルで起動中のアプリを開いて、Agent に画面を見せる
- 表示崩れ・押しても反応しないボタンなどを、実物を根拠に直させる
- `@Browser` で、その文脈を会話に載せる（[03-context.md](03-context.md)）

## Design Mode

ブラウザ表示中に **`Cmd + Shift + D`** で切り替えます。UI を**言葉で説明する代わりに、画面上で指す**ためのモードです。

| できること | 使いどころ |
|------------|------------|
| 要素をクリックして対象にする | 「このボタン」を言葉で特定しなくて済む |
| 複数選択する | 「この2つの間隔」など関係を指定できる |
| 画面に描き込む | 「ここをこう寄せて」を矢印で描く |
| 音声で指示する | 手を動かしながら喋る |

選んだ要素の**コード・レイアウト・周囲との関係**がまとめて Agent に渡ります。

> UI の修正依頼は言葉にすると長くなります（「ヘッダーの右側にある3つ並んだアイコンのうち真ん中」）。指せるなら指す方が速く、間違いも減ります。

## 向くこと / 向かないこと

- **向く**: 見た目の調整、余白・配置、「押しても動かない」系の不具合
- **向かない**: 計算ロジックやデータ構造の修正。これは普通に Agent へ依頼する

## 実習

1. 何か動くページを用意する（第2回で作った神経衰弱でよい）
2. Agents Window のブラウザで開く
3. `Cmd + Shift + D` で Design Mode にし、カードを1枚選んで次を依頼する

```text
選択したカードの角を丸くして、裏面の色をもう少し落ち着いた色にして。
他のスタイルは変えないで。
```

4. 差分を読んでから Keep する（画面から指しても、確認の手順は変わりません）
