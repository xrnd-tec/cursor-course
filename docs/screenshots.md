# スクリーンショット撮影台本

授業スライド用の画面キャプチャを、進行台本（[`courses/4sessions/`](../courses/4sessions/)）の順に撮るためのリスト。

撮る人が上から順に実行すれば、スライドに必要な画像が過不足なく揃うことを目指す。
第1回で **16枚**（うちスライド採用は15枚。`s01-14` は下記のとおり見送り）、第2回で **7枚**。撮影の所要時間は第1回で40〜50分（Agent の応答待ちを含む）。

---

## 撮影前の準備（全体で1回・10分）

画像の見た目が揃っていないとスライドが安っぽくなる。**最初に固定して、途中で変えない。**

### 環境を固定する

| 項目 | 設定 | 理由 |
|------|------|------|
| 最終画像サイズ | **1600 × 1000** に統一 | 16:10 を保ちつつ、コードとUIラベルを読みやすくする |
| テーマ | ダーク / ライトのどちらかに統一 | スライドの背景色に合わせて先に決める |
| エディタのズーム | `Cmd + 0` で既定に戻す | 拡大したまま撮ると文字サイズがバラつく |
| 通知 | おやすみモード ON | Slack 等のバナーが写り込む事故を防ぐ |
| サイドバー | ファイルツリーだけ表示 | 拡張機能パネル等が写るとノイズ |

### 写り込みを消す

- **他のリポジトリ / 業務ファイル**をエディタのタブから全て閉じる
- Cursor 右上の**アカウントアイコン・メールアドレス**が写る構図を避ける
- ターミナルを写す場合、プロンプトにマシン名やユーザー名が出ていないか確認する
- **ステータスバーの git blame 表示に注意** — カーソル行によって `<GitHubアカウント名> (2 weeks ago)` が出る。
  枚によって出たり出なかったりするため見た目も不統一になる。消すなら blame 表示をオフにするか、
  ステータスバーを切り落としてトリミングする

### リポジトリを初期状態にする

実習の初期状態（`applyDiscount` が未実装）でないと、台本どおりの画面にならない。

```bash
git switch main
git pull
git status          # クリーンであること
```

`practice/calculator.js` の `applyDiscount` が TODO のままであることを目視で確認する。

### 保存先と命名

- 保存先: `docs/images/session-01/` · `docs/images/session-02/`
- 命名: `s01-03-mode-menu.png`（`s{回}-{通し番号}-{内容}`）
- 手動撮影は `Cmd + Shift + 4` → `Space` → ウィンドウをクリック
- 自動撮影は Retina のウィンドウ画像（実機では `2880 × 1800`）を保存し、最後に `1600 × 1000` へ縮小する
- 1枚 500KB を超えたら縮小する（リポジトリが膨らむため）

#### s01-03 — Cmd+K のインライン入力欄

- **狙い**: 「Cmd+K は『ここだけ』」の説明
- **作り方**: `applyDiscount` 関数全体を選択 → `Cmd + K` → 入力欄が出た状態（まだ送らない）
- **写す範囲**: 選択範囲と入力欄が両方入るように

#### s01-04 — Cmd+K の実行結果（diff）

- **狙い**: インライン編集が「その場で差分になる」ことを見せる
- **作り方**: s01-03 の入力欄に `TODOコメントだけを、処理内容が分かる具体的な日本語に直して。コードは変更しないで。` と送り、差分が出た状態

#### s01-05 — Agent パネルを開いた直後

### 第4章 Ask と Agent — 0:30

#### s01-06 — モードメニューが開いた状態 ★重要

- **狙い**: 「モードをここで選ぶ」の説明。コース中で最も使う1枚

> **s01-07 / s01-09 / s01-10 の共通注意**
> この3枚は「Ask と Agent でモードチップが変わる」ことを見せる比較用。
> 全画面のままだとチップが小さく、3枚の見た目もほぼ同じになって比較にならない。

#### s01-07 — Ask モードになった状態

- **狙い**: 「モードが変わったことは、ここを見れば分かる」

#### s01-08 — `@` のサジェストが出ている状態 ★重要

- **狙い**: 「`@` でファイルを指定する」の説明
- **作り方**: 入力欄で `@practice/calc` まで打ち、候補リストが出た状態
- **注意**: 候補にファイル名が読めること

#### s01-09 — Ask の回答が返ってきた状態

- **狙い**: 「Ask は答えるだけで、ファイルは変えない」の証拠
- **作り方**: `@practice/calculator.js このファイルの役割を3行で説明して` を送り、回答が出きった状態
- **注意**: **差分が出ていないこと**がこの画像の主張。エディタ側も一緒に写す

#### s01-10 — Agent モードに戻した状態

- **狙い**: s01-07 と並べて「切り替わった」を見せる

#### s01-11 — Agent が実行中の状態

- **狙い**: 「待っている間はこう見える」。受講者が不安になるポイント

### 第5章 差分を読む — 0:45

#### s01-12 — diff ビュー ★最重要

- **狙い**: 「Keep の前に必ず diff を読む」— コース全体で一番大事なスライド
- **作り方**: Agent が `applyDiscount` を書き終え、緑（追加）と赤（削除）が出ている状態
- **注意**: 緑と赤が**両方**写っていること。追加だけの差分だと説明が弱い

#### s01-13 — Keep / Undo ボタン

- **狙い**: 「ここで受け入れるか戻すかを決める」
- **作り方**: s01-12 の状態で、ボタンがある部分を**拡大して**切り出す
- **注意**: ボタンの文字が読めること

#### s01-14 — Review を開いた状態 ⚠️見送り（スライド未使用）

  変更バー自体は `s01-12` と `s01-13` で写っているため、**この1枚はスライドで使わない**。
  ファイルは欠番を避けるため残す（`s01-15` 以降を繰り上げない）。
  Review 画面を見せたくなったら、撮り直したうえでスライドに足す

- **狙い**: 「実際にコードが変わった」
- **作り方**: Keep 後の `calculator.js`。`applyDiscount` が実装済みになっている

### 第6章 ハンズオン — 0:55

#### s01-16 — 課題Aの diff

## 第2回：バイブ → 仕様駆動（7枚）

対応する台本: [`session-02.md`](../courses/4sessions/session-02.md)

この回のスライドは**比較**が命。バイブ版と仕様版を必ず同じ構図で撮る。

> **撮影前に必ず**: 入力欄のモデルを **Auto ではなく特定のモデルに固定**してから撮り始める。
> Auto のままだと、バイブ版と仕様版で別のモデルが動き、比較にならない画像ができる。
> `s02-02` と `s02-05` は同じモデル・同じ切り出し範囲・同じ拡大率で撮ること。

### 第2章 バイブで作る — 0:05

#### s02-00 — モデルを固定した状態

- **狙い**: 「計測の前提を揃える」。この回で唯一、失敗すると全部の画像が無駄になる操作
- **作り方**: 入力欄のモデル表示（`Auto` / `High` など）をクリックし、モデル一覧が開いた状態。選んだ後の表示も撮っておく
- **写す範囲**: 入力欄まわりを拡大して切り出す
- **注意**: 選んだモデル名が読めること。台本の説明とスライドで**同じモデル名**を出す

#### s02-01 — バイブで作った神経衰弱（動作中）

- **狙い**: 「曖昧な依頼でも、動くものは数分で出る」
- **作り方**: `神経衰弱ゲームを作って。HTML + JS で、ブラウザで遊べるようにして。いい感じに。` の結果をブラウザで開いた状態
- **写す範囲**: ブラウザウィンドウ

### 第3章 増えていく変更量 — 0:20

#### s02-02 — 依頼3の diff（変更行数が見える状態）★重要

- **狙い**: 「つぎはぎで積み上がる変更量」。第2回の主張はここに乗っている
- **作り方**: 「制限時間＋デザインもかっこよく」を送った後の diff。**変更行数（+/-）の表示が写るように**
- **注意**: 行数が読めないと意味がない。数字部分を拡大した2枚目も撮っておくと安全

#### s02-03 — 計測表を埋めた状態

- **狙い**: 授業中に全員で埋めた表をスライドに残す
- **作り方**: 板書 or スライドに書き込んだ計測表（依頼1〜3 × 変更行数・3機能の生存）を撮る
- **注意**: 画面キャプチャでなく写真でもよい

### 第4章 仕様を書く — 0:30

#### s02-04 — 仕様を渡した直後の Agent 画面

- **狙い**: 「新しいチャットに仕様を貼って渡す」型を見せる
- **作り方**: 新規チャットに最小仕様を貼り付けた状態（送信前でも可）

#### s02-05 — 仕様版の追加依頼の diff ★重要

- **狙い**: s02-02 と**並べて**「同じ機能追加でも差分がこれだけ違う」を見せる
- **作り方**: 仕様版に手数表示を追加した diff。変更行数が写るように
- **注意**: s02-02 と**同じ切り出し範囲・同じ拡大率**で撮る。並べたときに比較にならない

### 第6章 持ち帰るもの — 1:20

#### s02-06 — 「3回目以降は 0.5 秒」の挙動比較

- **狙い**: 仕様にしか書いていないルールが、バイブ版には存在しないことを見せる
- **作り方**: バイブ版と仕様版の両方で3回ミスしたときの挙動。動画が難しければ、該当コードの有無を diff で見せてもよい
- **注意**: この1枚が「仕様を書く意味」の最も強い証拠になる

## 実機確認で見つかった改善点

2026-08-20 に Cursor 3.16 の実機を Computer Use で操作し、第1回の16枚を通し撮影した結果。

### 教材・操作手順

- **Agent 関連の3つのショートカットは別コマンド**
  - `Cmd + I` / `Cmd + L`: `Focus Chat Input`。Agent UI が閉じた IDE 画面から `Cmd + I` を押すと、実機では `Cursor Agents` が前面に出て入力欄へ移った。
  - `Shift + Cmd + L`: `New Agent with Context`。新しい Agent をコンテキスト付きで開始する。
  - `Option + Cmd + J`: `Toggle Agents`。Agent UI の表示状態を切り替える。
  - したがって、`session-01.md` と本台本の `Cmd + I` は機能的に正しく、他の2つの表示とは矛盾しない。
  - 「Agent パネルを開く」よりも「Agent の入力欄を開く／フォーカスする」と表現すると、パネル表示と Agents Window の両方を含められてより正確。
  - キーバインドを利用者が変更している可能性もあるため、ショートカットだけでなく画面上のボタンから開く手順も併記すると安全。
- **モードメニューは5項目だった**
  - Cursor 3.16 では `Agent` / `Plan` / `Debug` / `Multitask` / `Ask`。
  - `Shift + Tab` はメニューを開かず、モードを順送りした。メニューの撮影・説明では現在のモード名をクリックする。
- **レビュー操作の表記が変わっている**
  - エディタ上の各差分は `Keep`（採用）/ `Undo`（取り消し）。複数の差分があるときは各差分を確認する。
  - Agent パネル下部には変更一式に対する `Undo` / `Keep` / `Review` が表示された。
  - **Cmd+K のインライン入力欄は今も `Accept` / `Reject` 表記**（`s01-04` に `Reject` / `Accept ⌘⏎` と `Undo ⌘N` / `Keep ⌘Y` が同時に写っている）。
    行単位の差分バーが `Keep` / `Undo`、インライン編集の確定が `Accept` / `Reject` で、別物として説明する。
  - `Restore Checkpoint` は旧版向けの補足として扱う。
- **元の Cmd+K 依頼は変更が発生しなかった**
  - `applyDiscount` のコメントは最初から日本語なので、`コメントを日本語に直して` では差分が出ない。
  - 対象と完了条件を具体化し、`TODOコメントだけを、処理内容が分かる具体的な日本語に直して。コードは変更しないで。` に変更した。

### 撮影画面

- **`s01-01` はそのまま使用可能**
  - `cursor-course/`、ファイルツリー、`practice/calculator.js`、Agent パネルが閉じた状態を確認できた。
  - 注釈用の余白もあり、導入スライドの素材として成立する。
- **`s01-02` は `applyDiscount` 周辺をトリミングする**
  - `const discounted =` に対して灰色の続きが表示され、「Tab は続きを提案する」という狙いには合致した。
  - 全画面のままだと提案文字が小さいため、コード周辺だけを切り出してスライドに載せる。
- **未完成コードのエラー表示は想定内だが、説明のノイズになる**
  - Tab の提案を待つ間はコードが未完成なので、赤い波線・問題数・赤いファイル名が表示される。
  - スライドでは必要なコード部分だけを切り出すか、「入力途中のため一時的にエラーが出ている」と注釈する。
- **`s01-04` の自動撮影では同義の英語プロンプトを使用した**
  - 日本語の貼り付けが不安定だったため、画面上は `Change only the TODO comment...` だが、生成された日本語コメントと差分の狙いは台本に一致する。
  - プロンプト本文を教材として読ませるスライドに使う場合だけ、日本語版へ撮り直す。diff の説明素材としてはそのまま使用できる。
- **撮影画像を作業中のリポジトリへ直接保存しない**
  - `docs/images/` を作成した直後から、ファイルツリーや Git 表示に新規フォルダ・変更マークが写り込んだ。
  - 撮影中は一時フォルダへ保存し、全画面を撮り終えてから `docs/images/` へ移す。

### 画像仕様

- **Computer Use の観察画像と納品用画像を分ける**
  - 操作用の観察画像は `1229 × 768` だったが、macOS のウィンドウ直接キャプチャでは Retina の `2880 × 1800` を取得できた。
  - 納品用は高解像度のPNGから `1600 × 1000` へ縮小した。第1回の16枚はすべて500KB未満。
- **必要な画像だけ切り出す**
  - `s01-02` はコード周辺、`s01-13` は `Undo` / `Keep` 周辺を切り出し、最終サイズを `1600 × 1000` に揃えた。
  - **スライド側でさらに切り出す画像は、縮小前の高解像度PNGも残す。** `1600 × 1000` から 1/3 を切り出すと約 530px しか残らず、
    スライドで 800px 幅に置くと拡大になってぼける。切り出し前提の画像（`s01-02` `s01-13` など）は原本を捨てない。
  - Ask と Agent は会話の有無で入力欄の位置が変わるため、同一座標よりもモード名の可読性を優先する。

### 操作中の安全策

- **Computer Use の操作中は同じ Mac を手動操作しない**
  - フォーカス、カーソル位置、入力先が変わり、誤操作や撮り逃しにつながる。
  - 手動作業が必要な場合はいったん撮影を停止し、再開時に画面状態を読み直す。
- **一時入力を戻した後は内容と Git 差分の両方を確認する**
  - Undo は入力単位で複数回必要になる場合がある。
  - 次の撮影へ進む前に、対象ファイルが初期状態へ戻ったことと、意図しない差分がないことを確認する。
